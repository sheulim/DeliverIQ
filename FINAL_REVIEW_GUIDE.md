# DeliverIQ — Final Review & Sign-off Guide

## Product positioning
DeliverIQ is the Intelligence Layer for Project Delivery.

It does not attempt to replace Jira, Azure DevOps, Asana or Microsoft Project.
It brings project and programme delivery data together and helps leaders answer:
- Are we on track?
- What needs attention?
- What changed?
- What happens if this slips?
- Which commitments are slipping?
- What decisions are blocking progress?
- Are we delivering intended value?
- Do we have enough capacity?
- Are we likely to exceed budget?
- What will this change affect?

## Sign-off walkthrough
1. Create/sign in as a user.
2. Create a project with AI.
3. Review project dashboard.
4. Add RAID items.
5. Add dependencies and run slip simulation.
6. Add actions and decisions.
7. Create a meeting and extract actions.
8. Add stakeholders and generate a communication.
9. Add benefit / OKR values.
10. Add capacity and run delivery forecast.
11. Add budget / costs and run financial review.
12. Add a change request and run impact analysis.
13. Ask the AI PM Workspace a cross-project question.
14. Create a programme and review cross-project intelligence.

## Recommended sign-off criteria
- Navigation is understandable to a non-technical PM.
- AI never silently changes user data.
- AI outputs are clearly advisory.
- Deterministic calculations are distinguishable from AI interpretation.
- Project data is user-isolated by RLS.
- Executive views answer the core governance questions quickly.
- Users can move from insight to action without copying data manually.

## Known limitations before commercial launch
- Many screens still use inline CSS / prototype-grade visual styling.
- AI routes still use manual JSON parsing in several builds.
- Automated test coverage is not yet comprehensive.
- Jira / Azure DevOps are architecture placeholders, not live OAuth integrations.
- CSV import is architecture-ready but not a polished import wizard.
- Billing / subscriptions are not implemented.
- Enterprise SSO is not implemented.
- Notification engine is not implemented.
- Email sending is intentionally not automatic.
- Strict audit coverage for every mutation should be expanded.
